# Encoder-Decover
## 1. 왜 Encoder–Decoder가 필요할까?

기존 RNN은 과거 데이터를 순서대로 입력받으면서 다음 값을 예측할 수 있었지.
그런데 교안 28페이지에서는 이런 문제를 제기해.
미래 시점의 외부 입력 데이터가 없다면 어떻게 여러 시점의 미래를 예측할까?
그래서 과거 정보를 먼저 요약하고, 그 요약된 정보만으로 미래 시퀀스를 생성하는 Encoder–Decoder 구조를 소개해


쉽게 말하면, Encoder–Decoder는 과거 데이터를 한 번 정리한 다음, 그 정보를 가지고 미래를 여러 번 예측하기 위해 필요한 구조야.

### 1. 일반 RNN으로 예측하면?

예를 들어 최근 5일간의 주가가 있다고 해보자.
`100 → 110 → 120 → 130 → 140`
일반 RNN은 이 데이터를 보고 내일 주가를 `150`이라고 예측할 수 있어.
그런데 내일뿐 아니라 앞으로 10일간의 주가를 예측하고 싶다면?
미래의 실제 주가는 아직 모르잖아.

### 2. 그래서 Encoder–Decoder를 사용하는 거야
Encoder는 과거 흐름을 기억하고, Decoder는 그 기억을 이용해 미래 값을 만들어내는 거지.
### 3. 그런데 일반 RNN도 계속 예측할 수 있잖아?
맞아. 일반 RNN도 자기 예측값을 다시 입력하면 여러 날을 예측할 수 있어.
그래서 Encoder–Decoder가 반드시 필요한 건 아니야.
차이점은 과거 정보를 읽는 역할과 미래를 생성하는 역할을 명확하게 분리했다는 거야.
이렇게 하면 과거에 사용한 정보와 미래에 사용할 정보가 다르더라도 유연하게 모델을 구성할 수 있어.


# Attention RNN 
- 사실 Attention 이라는 개념이 Encoder- Decoder에서 왔다.
- 보통 Decoder 에게 Encover가 주는 값은 모든 시리얼 결과가 반영된 마지막 logit이다.

# 갑자기 궁금해짐 Q K V
![[Pasted image 20261111103822.png]]

공식에 관련된 코드
```
keys = self.W_key(x)
queries = self.W_query(x)
values = self.W_value(x)

# ① Q와 K의 내적으로 관련성 점수 계산
attn_scores = queries @ keys.transpose(1, 2)

# ② 미래 토큰을 참조하지 못하도록 마스킹
attn_scores.masked_fill_(
    self.mask.bool()[:num_tokens, :num_tokens],
    -torch.inf
)

# ③ Softmax로 Attention 가중치 계산
attn_weights = torch.softmax(
    attn_scores / keys.shape[-1]**0.5,
    dim=-1
)

# ④ 가중치를 V에 곱해 최종 결과 생성
context_vec = attn_weights @ values
```
