# 기본 파인 튜닝

prompt로 튜닝을 한다는 거같음. prompt도 똑같이 input 과 target을 만들어 줘야하는데, 맨 첫단어만 input나머지는 target 이런식으로 shifting 해줬을때와 같은 방식을 씀.

batch context 중 가장 긴 프롬프트를 가져와서 프롬프트 길이가 길면 짜르고, 짧으면 패딩 처리하면됨. target은 masking을 -100으로함. 
-> target 은 input이 다음 문장을 맞춰야할 대상이므로 padding까지 맞출필요없음
-> 때문에 padding쪽은 -100으로 해서 loss값을 계산조차 하지 않게함. 

```
mask = targets == pad_token_id
indices = torch.nonzero(mask).squeeze()

# 타겟에서 패딩 토큰인 부분은 ignore_index(-100)로 바꿔서 CrossEntropyLoss 계산 시 무시되게 함
# 패딩이 시작되는 지점 이후의 모든 타겟 값을 -100으로 설정 # region [패딩 마스킹 처리] if indices.numel() > 1: 
	targets[indices[1:]] = ignore_index 

```

SFT는 모델에게 사람의 답변 방식을 학습시키는 과정이고, DPO는 그 모델이 사람의 선호도에 맞는 답변을 하도록 추가로 조정하는 과정이야.

# DPO
### 💡 주요 핵심 포인트

1. **DPO의 원리**: 일반적인 학습과 달리 **두 개의 모델**이 필요합니다.

- `policy_model`: 학습이 되어 업데이트되는 모델 (우리가 훈련시키는 모델).
- `reference_model`: 학습되지 않고 고정된 상태로 비교 기준이 되는 모델 (**보통 SFT가 완료된 모델 사용**).

2. **데이터 구성**: `(Prompt, Chosen, Rejected)` 세 가지가 한 세트입니다. 모델이 `Chosen`(선호) 쪽으로 확률을 높이고 `Rejected`(비선호) 쪽으로 확률을 낮추도록 유도합니다.
3. **마스킹(Masking)**: `custom_collate_fn`에서 프롬프트 부분을 `False`로 마스킹합니다. 모델이 질문(Prompt)을 생성하는 능력은 평가하지 않고, 질문에 대한 **답변(Response)** 부분의 확률만을 가지고 Loss를 계산하기 위함입니다.
